# モジュラーモノリスとSpring Modulith

このリポジトリは、Kotlin、Spring Boot、およびSpring Modulithを使用して実装された**モジュラーモノリス**アーキテクチャのデモです。各モジュール内で**クリーンアーキテクチャ**の原則を適用し、保守性とテスト容易性を確保しています。

[English (英語)](./README.md)

## 主な特徴

- **モジュラーモノリス**: アプリケーションはモノリスとして構成されていますが、疎結合なモジュール（`catalog`、`order`など）で構成されています。
- **クリーンアーキテクチャ**: 各モジュールはクリーンアーキテクチャの原則に従い、関心事をドメイン、アプリケーション、インフラストラクチャ、プレゼンテーション層に分離しています。
- **Spring Modulith**: Spring Modulithを使用してモジュールの境界を検証し、依存関係を管理することで、モジュールがアーキテクチャの制約に違反しないようにしています。
- **依存関係の制御**: 公開APIは明示的に定義され、内部の実装詳細は隠蔽されることで、強力なカプセル化を強制しています。

## プロジェクト構成

プロジェクトは以下のモジュールで構成されています：

- **app**: メインのアプリケーションエントリポイント（Spring Bootアプリケーション）。
- **modules**:
  - **catalog**: 商品カタログを管理します（クリーンアーキテクチャの実装例）。
    - `domain`: コアビジネスロジックとエンティティ。
    - `application`: ユースケースとアプリケーションサービス。
    - `infrastructure`: インターフェースの実装（リポジトリ、外部サービス）。
    - `presentation`: RESTコントローラー。
  - **order**: 注文を管理します。
  - **common**: 共有ユーティリティと横断的な関心事。

## 始め方

### 前提条件

- DockerおよびDocker Composeがインストールされていること。
- JDK 21（Dockerを使用せずにローカルで実行する場合）。

### Dockerでの実行

Docker Composeを使用して、アプリケーションとデータベースを簡単に起動できます：

```bash
docker-compose up --build
```

アプリケーションは `http://localhost:8080` で利用可能になります。

### テストの実行

Spring Modulithの検証テストを含むテストを実行するには、以下のコマンドを実行します：

```bash
./gradlew test
```

## アーキテクチャの詳細

各モジュールは独立するように設計されています。`app`モジュールはすべての機能モジュールを集約して、実行可能なアーティファクトを作成します。

### 依存関係のルール
- **ドメイン（Domain）**層は他のどの層にも依存しません。
- **アプリケーション（Application）**層はドメイン層に依存します。
- **インフラストラクチャ（Infrastructure）**および**プレゼンテーション（Presentation）**層は、アプリケーション層とドメイン層に依存します。

Spring Modulithにより、循環依存が存在しないこと、およびモジュールが他のモジュールの許可された公開コンポーネントにのみアクセスすることが保証されます。
